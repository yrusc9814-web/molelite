# P7 任务 B 修复口径（Hark 拍板，2026-11-19）

1. 方向：宁可漏删，不可误删。拿不准是不是这个应用的文件，就不收（或只展示不删）。
2. 改法优先级：先“收紧/加边界/加锚定”，其次“加归属校验”（读 Info.plist、容器 metadata、plist 的 CFBundleIdentifier 等），最后才“新增保护名单”。不要大改结构，不要动与本条无关的代码。
3. 报告里的“建议”是参考，按第 1、2 条挑最小、最稳的改法。
4. 漏找类（B2-*）：只在能确定归属时补收；补收的路径必须同样经过现有守卫（G-*）。
5. 不改 review-only 机制（B:2344-2353 那段清空系统文件的代码，注释写着 Do NOT remove）。
6. 每条必须加回归测试：新文件 tests/p7b_<编号>.bats，至少一个“修复前会误删/漏找、修复后正确”的用例，fixtures 放临时 HOME，绝不碰真实文件。
7. 兼容 bash 3.2（macOS 自带）：不用关联数组、不用 ${var,,}、不用 mapfile。
8. 提交：只 git add 本条改动的文件，消息 "P7b <编号>: <一句话>"，身份 git -c user.name=Hark -c user.email=hark@local。
9. 无需改代码的（例如已有守卫完全覆盖）：不提交，在结果里写 status=kept 和理由+代码行号。
